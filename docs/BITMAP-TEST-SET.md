## Binding evidence added

Captured HmiMain3D SHA-256 `fe770d1957fdfcd250d1f8cf7fba0e9a7c25e8c053e59f04f3274055fedda935`:

- CarouselState writer `0x2926554` emits nested base +4, scalar +0x10, element vector +0x14 and three trailing fields +0x20/+0x24/+0x28.
- Element vector writer `0x29264c4` advances object addresses by 0x14 bytes and uses nested virtual serialization.
- CarouselElement writer `0x292008c` serializes four member addresses +4/+8/+0xc/+0x10 through `0x27f0368`, which calls output-stream vtable slot +0x28. Field meanings and image-reference position are **not established**.
- Entertainment wrapper `0x29208f8` and Voice wrapper `0x2924740` both delegate their nested +4 object through `0xf87334`. That helper invokes the nested object's own writer at vtable +0xc. Treating the wrapper as the full layout would miss its concrete nested type.

The next binding work is the concrete nested object and CarouselElement construction/call sites: identify which member receives a bitmap RID, correlate with retained messages, and identify selective removal. Serializers alone cannot prove receiver behavior.
